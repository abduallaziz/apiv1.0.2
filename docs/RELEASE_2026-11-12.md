## 1. ZATCA e-invoicing (Phase 2 / Fatoora) — the headline

Full implementation, **validated against ZATCA's real sandbox** (all document types + all VAT
categories → `PASS`, 0 errors/0 warnings), and the demo is **live** (real sales REPORT to ZATCA).

See **`docs/ZATCA_IMPLEMENTATION.md`** for the complete reference. In brief:
- Signed UBL 2.1 documents (simplified B2C, standard B2B, credit/debit notes), SHA-256 hash chain
  (ICV/PIH), ECDSA secp256k1 signature, XAdES, 9-tag QR, CSR, CSID.
- Gateway (`fatoora.gateway.ts`): compliance CSID, compliance checks, production CSID,
  reporting/clearance; sandbox routes to the compliance endpoint.
- Onboarding + device registry + queue; Settings → "الفوترة الإلكترونية" web screen.
- Standard vs simplified chosen by buyer VAT; credit notes for full cancel + partial return; VAT
  categories S/Z/E/O with VATEX exemption reasons.
- Four real-validator fixes (mandatory customer party; QR tags as base64 text; UTC QR timestamp;
  B2B supply date). Demo fix: sandbox devices stay on the compliance CSID (production creds 401).
- Migrations 268–272. Flags `ZATCA_ENABLED` / `ZATCA_GATEWAY` / `ZATCA_KEY_ENC_KEY` (off by default).
- Decisions: one device per branch; invisible/conditional onboarding PAUSED (ZATCA applies only to
  VAT-registered tenants).

## 2. Invoice designer v2 (API + web)

Extended invoice/receipt template: style, language, item columns, totals lines, labels, title,
header/terms text, custom fields, date/time format, and the invoice-number format (prefix/padding).
Strict validation on save, lenient repair on read; required receipt elements have no toggles.
Files: API `print-template.util.ts`, `print.types.ts`; web `InvoiceStyleSections.tsx`,
`PrintDesignerPage.tsx`, `lib/print/renderReceipt.ts`, `print.json` messages.

## 3. Sequential invoice numbers

`orders.invoice_no` + `invoice_sequences` + `fn_next_invoice_no()` inside the sale tx (gap-free via
rollback, duplicate-free via row lock), format from the template. Shown in POS and on the receipt
(`order_number = invoice_no ?? last6`). Migration 268. Required by ZATCA.

## 4. Simplified expenses section (web)

Reworked the expenses area to one list: add any expense, add a recurring expense, and one button to
add a category — nothing more. Recurring expenses page is view + edit/delete only (cannot add an
expense from there). New `AddCategoryDialog.tsx`; default-department handled silently;
`expenses-v2.json` messages.

## 5. Kitchen auto-print switch (API + web)

Independent on/off for automatic kitchen-ticket printing (`printer_settings.kitchen_auto_print`),
separate from the customer receipt. API `update-tenant-profile.dto.ts`, `print.types.ts`; web
Settings switch + `ReceiptModal.tsx`.

## 6. Dashboard follows the selected branch (web)

Every dashboard figure and widget now respects the branch chosen in the branch switcher (branch_id
forwarded to the reports API). Fixes figures that previously ignored the selected branch.
`DashboardOverview.tsx`, `reports.api.ts`.

## 7. Receipt tax-mode line removed (web)
